# NAS 主动 HTTPS 拉取验证结果

2026年10月16日，在用户指定的真实 NAS 上通过 SSH 标准输入运行临时 Python 探针。保留 SSH 主机密钥校验和 HTTPS 证书校验，没有更改网络路由、代理、系统证书、Docker 服务或任务计划。

| 检查 | 结果 |
| --- | --- |
| 运行环境 | Linux x86_64、Python 3.12.3、OpenSSL 3.0.13、Docker 可用 |
| 主动 HTTPS 下载 | NAS 成功下载固定 GitHub 提交中的公开 LICENSE 样本，34020 字节 |
| 摘要一致性 | SHA256 与本地样本一致 |
| 校验后替换 | 临时文件完整下载且摘要匹配后使用同目录 replace |
| 错误摘要 | 第二次下载故意指定错误摘要，拒绝替换并保持前一文件逐字节不变 |
| 明文 HTTP | 在发出请求前拒绝 |
| 清理 | 无残留 partial 文件，临时目录退出后确认不存在 |

复现命令为 `npm run verify:nas`，NAS 目标和密钥路径通过环境变量传入，不存入仓库。传输脚本按原始 LF 字节输入，避免 Windows 文本管道在 Linux 上产生 CRLF 错误。

这证明家宽 NAS 可以主动连接公网 HTTPS、校验并保留可靠的旧副本，不要求外部连接 NAS。它不代表已完成 Cloudflare 专用鉴权、加密备份格式、历史保留、定时任务、断电恢复或离线解密，这些内容保持后续验证状态。
