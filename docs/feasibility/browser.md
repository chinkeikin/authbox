# Chrome 浏览器密码学验证结果

2026年10月16日，使用本机 Chrome 155.0.8059.41 的隔离 headless 配置执行 `npm run verify:browser`。页面只从本机回环地址加载已打包代码，不使用日常浏览器资料。

| 检查 | 结果 |
| --- | --- |
| 受限 CSP | 仅同源脚本及 wasm-unsafe-eval，禁止远程脚本，运行通过 |
| AES 256 GCM 互通 | Chrome 与 Node 双向解密通过，结果与 PHB110 验证使用同一固定向量 |
| 篡改拒绝 | 密文、标签、nonce、AAD、key 五类均被拒绝 |
| Argon2id 标准向量 | RFC 9106 第 5.3 节通过 |
| 保险库候选 KDF | hash-wasm 4.12.0，64 MiB、3 次迭代、并行度 1，32 字节输出 |
| 与 Node 派生结果核对 | 三次均完全一致 |
| 三次浏览器 KDF 墙钟时间 | 124.4、121.1、122.6 ms，包含首次实例化及后续调用 |

结果支持在浏览器侧继续采用 WASM KDF 候选，与 Workers 不能动态编译的限制分别处理。此电脑的耗时不能外推手机表现，也不因此减少密码学成本参数。

本次验证对象是受限 CSP 下的普通 Chrome 页面，不是已安装的 MV3 扩展；扩展安装、权限、session 存储、休眠恢复和自动锁定仍须在对应工程中验证。手机 JCA 验证共享向量调整后再次通过并清理临时文件。
