# AuthBox 第一版需求与技术方案

版本：V1 评审稿

日期：2026年10月16日

状态：需求与技术设计；阶段 1 可行性验证进行中，已验证和待验证项见 [验证进度](feasibility/README.md)，正式业务功能尚未实现

第一版提供手机端完整管理、Chrome 扩展只读取码、自建账号及可选 Google 绑定。验证密钥和管理信息在客户端加密后同步到 Cloudflare，各设备本地生成验证码；NAS 主动下载可独立恢复的加密备份。目标是账号多时快速找到验证码，同时覆盖手机丢失、多设备使用、误删和云端不可访问的恢复场景。

文中的“必须”是第一版需求，“建议”和默认值是实现建议，待验证事项在末尾集中列出。手机系统已确认为第一版仅支持 Android，后续版本增加 iOS；第一版保持加密格式、同步协议和备份格式的跨平台兼容要求。

## 1 产品范围

### 1.1 已确认需求

| 模块 | 第一版范围 |
| --- | --- |
| 手机端 | 第一版仅 Android；支持账号导入、增删改查、分组、标签、收藏、排序、搜索、备份恢复、设备及账号管理；iOS 后续增加 |
| Chrome 扩展 | 只读查看、搜索筛选、复制验证码、拉取同步、离线取码、自动锁定 |
| 平台账号 | 独立用户名和密码登录，独立账号恢复途径 |
| Google 登录 | 可选绑定已有平台账号，用于快捷登录，不作为唯一登录或恢复依据 |
| 加密同步 | 端到端加密，本地可用，云端负责密文存储、权限和版本控制 |
| 恢复 | 新设备恢复、忘记密码处理、误删恢复、离线文件恢复 |
| NAS 备份 | NAS 主动连接云端并拉取加密快照，不要求家宽公网入站能力 |

### 1.2 第一版范围边界

第一版以个人使用和一个账号管理一个个人保险库为目标。多部手机可获得管理权限，多个 Chrome 实例可获得只读权限。NAS 是备份接收端，不是同步主服务器。

短信、微信、QQ 登录，iOS 客户端、团队共享、多人协作、网页自动填码、浏览器页面扫描、Windows 独立客户端和 NAS 完整后端自托管不在本版范围内。Google 绑定属于可选功能，未配置 Google 时，其余功能必须完整可用。

第一版支持标准 TOTP，覆盖 HMAC SHA1、SHA256、SHA512、6 或 8 位及二维码指定的刷新周期。HOTP 和平台专有验证方式在导入时明确提示不支持，不能错误转换成 TOTP。TOTP 依据 [RFC 6238](https://datatracker.ietf.org/doc/html/rfc6238) 实现并用标准测试向量验证。

## 2 端与权限

| 能力 | 已授权手机 | Chrome 只读设备 | NAS 备份凭据 |
| --- | --- | --- | --- |
| 拉取当前保险库密文 | 允许 | 允许 | 仅通过备份接口 |
| 查看和复制验证码 | 允许 | 允许 | 不提供 |
| 添加修改删除验证账号 | 允许 | 禁止 | 禁止 |
| 修改分组标签收藏排序 | 允许 | 禁止 | 禁止 |
| 导入导出与历史恢复 | 允许 | 禁止 | 仅下载完整加密备份 |
| 修改平台账号或绑定 Google | 允许，需重新认证 | 禁止 | 禁止 |
| 审批管理设备与备份凭据 | 允许，需管理授权 | 禁止 | 禁止 |
| 注销当前设备会话 | 允许 | 允许 | 撤销由手机操作 |

Chrome 可以保存本机搜索条件、展开状态、主题和锁定时长，不上传或改变保险库内容。同步状态只显示拉取结果、云端版本、最后成功时间和错误，不出现“待上传修改”。

“只读”指服务端拒绝其设备凭据执行保险库和管理写入，不是禁止登录、会话续期、注销等控制请求。只读客户端生成离线验证码必须持有可解密的验证密钥，因此无法从密码学上阻止已解锁设备复制密钥；没有导出界面不等于密钥不可被提取。

## 3 手机端需求

### 3.1 验证账号与快速查找

| 功能 | 要求 |
| --- | --- |
| 首页 | 显示平台、自定义名称、账号、当前验证码、剩余时间和同步状态 |
| 分组 | 支持新建、重命名、排序、删除；一个验证账号归属一个分组，保留“未分组” |
| 标签 | 一个验证账号可添加多个标签，支持按标签筛选 |
| 收藏 | 收藏与取消收藏由手机管理；默认提供“收藏”快捷入口 |
| 排序 | 手机可手动调整组内顺序，排序结果同步到各端 |
| 搜索 | 在本地按平台、名称、账号、备注和标签搜索，忽略大小写 |
| 复制 | 点击复制验证码，显示复制反馈；不把复制行为写入云端业务记录 |
| 批量操作 | 多选移动分组、设置标签、收藏、移入回收站 |
| 编辑 | 更改展示信息；更换密钥或算法参数需确认并保留可恢复历史 |

删除分组时，将其账号移入“未分组”，不连带删除验证账号。删除标签时只移除标签关联。账号名称和平台可重复，以稳定 UUID 识别，避免同名账号覆盖。

### 3.2 添加与迁移

- 支持相机扫描标准 `otpauth://totp` 二维码、手动输入密钥及从本地图片解析二维码。
- 支持 Google Authenticator 导出迁移二维码，处理多张二维码的批次顺序、完整性及重复扫描。
- 批量导入先展示账号列表、支持情况和重复项，用户确认后提交；迁移批次不完整时不能显示“全部导入成功”。
- 校验 Base32 密钥、算法、位数、周期和字段长度，未知格式明确拒绝；不得直接打开二维码中的外部链接。
- 同一条目重复导入时提供跳过或保留两个的选择，禁止按邮箱或名称自动覆盖。重复判断在客户端解密后进行。
- 扫码图片、二维码内容和原始密钥均在本地处理，不上传识别服务，不进入日志或分析系统。

Google 迁移兼容需要实现和真机验证，不能以“普通二维码扫描成功”代替迁移验收。导入后先与原验证器核对验证码并实际登录，再由用户处理旧应用。

### 3.3 设备与设置

手机端提供设备列表、授权角色、会话撤销、Google 绑定管理、平台密码修改、保险库密码修改、恢复材料生成、备份凭据管理和同步诊断。

默认后台锁定延迟建议为 30 秒，可设置为立即或其他短时长；设备重启后需要重新解锁。指纹或设备凭据只负责本机便捷解锁，不承担新设备恢复。剪贴板清理仅在系统允许且仍是本应用写入内容时执行，不能覆盖用户后来复制的文本。

## 4 Chrome 扩展需求

### 4.1 使用流程

首次安装后，以平台账号或已绑定 Google 登录，获得只读会话，下载保险库密文，再输入保险库密码解锁。后续保留登录状态与加密缓存，按锁定策略重新解锁，无需手机在线。

工具栏弹窗提供收藏、分组切换、标签筛选、搜索、验证码和倒计时、复制、手动刷新同步及锁定。账号较多时可打开完整标签页，但所有界面保持只读。

扩展没有新增、编辑、删除、导入、导出、调整收藏、管理分组、设备审批、Google 绑定或密码重置入口，也不提供网页自动填码。

### 4.2 存储与运行

采用 Manifest V3。代码及密码学依赖打包随扩展发布，不从远程加载可执行脚本；Google 快捷登录通过受支持的浏览器授权流程完成，不把网页端远程登录脚本直接注入扩展。

持久层只存密文、密码保护后的保险库密钥封装及必要会话资料。解锁后的密钥仅存在受信任扩展上下文的内存或 `chrome.storage.session`，禁止放进 `storage.sync`、普通网页存储或内容脚本。持久存储访问级别限制为受信任扩展上下文。本版无需内容脚本及所有网站访问权限，只申请云端 API、存储、用户主动复制和授权流程所需权限。

Chrome 后台会休眠，不能把安全状态只放在 Service Worker 全局变量或依赖连续计时。每次打开、恢复焦点和使用密钥前检查锁定截止时间；浏览器重启、扩展重载或更新后重新解锁。会话存储的清理行为见 [Chrome 存储文档](https://developer.chrome.com/docs/extensions/reference/api/storage)，后台限制见 [Service Worker 生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。

闲置锁定默认建议 5 分钟，计时只由用户交互延长，后台同步不得延长解锁状态。锁定后清空解密数据与密钥引用。浏览器环境不能保证物理内存被完全擦除，不将此描述为硬件级密钥保护。

公司管理的电脑可能限制扩展安装或开发者模式，本机部署方式需在实际电脑上验证；正式商店发布审核不作为本地开发完成的前提。

## 5 自建账号与 Google 绑定

### 5.1 平台账号

以用户名作为主登录名，建议固定小写 ASCII 规则并建立唯一索引；邮箱为可选联系信息，本版不依赖短信或邮件验证码。注册先面向个人自用，默认采用部署时配置的一次性邀请凭据，避免公开注册和滥用。邀请凭据由首次手机安装输入，不内置到应用包。

注册流程在手机完成：创建平台账号及首个管理设备，创建保险库，设置保险库密码，生成恢复材料，确认已另存后完成初始化。服务端只保存登录密码的慢哈希、盐和参数，不保存明文或可解密的登录密码。

账号登录密码与保险库密码是两个独立秘密：前者证明身份，后者在本地解密数据。第一版不把登录密码用作保险库密钥，不把修改平台密码等同于修改保险库密码。

### 5.2 会话与设备角色

建议短期访问令牌有效期 10 分钟，刷新会话闲置有效期 30 天、绝对有效期 90 天。刷新令牌轮换并检查重复使用，服务端只保存其哈希。具体时长可配置，撤销、密码恢复和风险事件优先于续期。

服务端为每个会话绑定 `user_id`、`device_id`、`role`、会话版本及撤销状态。敏感读写均检查设备当前状态；不只依赖 JWT 到期，从而允许联网时立即阻止被撤销设备继续拉取。刷新也不得提升原始权限。

为落实 Chrome 的只读要求，客户端提交 `client_type=mobile` 不能直接换取写权限。账号登录默认只能建立只读或待授权会话；首个管理设备在注册事务中建立，后续管理设备须由已有手机批准，或通过独立账号恢复码重新授权。手机管理设备另持有不可随意复制的设备私钥，用于管理授权挑战，服务端保存公钥。签名采用成熟实现并绑定一次性挑战、目标操作和有效期。

因此，持有 Chrome 只读会话不能自行创建管理设备、设置备份凭据或绑定第三方身份。角色由服务端授权记录决定，不靠浏览器标识、客户端内置密钥或 User Agent 判断。

### 5.3 Google 快捷登录

Google 只绑定已有平台账号，不在首次 Google 登录时按同名邮箱自动合并或创建另一个保险库。手机在已有管理授权下重新验证平台密码，发起 Google 授权，服务端验证身份后绑定 `(issuer, sub)`；同一个 Google 身份不得绑定多个平台账号。

只申请 `openid`、`email`、`profile`。校验签名、`iss`、`aud`、`exp`、授权状态和防重放参数，邮箱用于展示。Google 的稳定身份标识及令牌验证要求见 [官方验证指南](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token)。

Google 登录只替代本次平台密码输入，不自动解密保险库，也不自动授予新设备管理权限。Google 不可用、账号无法登录或用户未绑定时，用户名密码及恢复码流程继续可用。解绑前必须确保独立登录方式可用，并撤销相应 Google 登录产生的会话。

接入需创建 Google Cloud 项目及 OAuth 客户端，配置应用信息和回调。个人自用有验证豁免，基本身份权限适用特殊测试规则；公开发布及展示自定义品牌时可能需要品牌验证。分别依据 [接入配置](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid)、[用户范围规则](https://support.google.com/cloud/answer/15549945) 和 [验证豁免](https://developers.google.com/identity/protocols/oauth2/production-readiness/brand-verification) 执行。

### 5.4 登录密码哈希与 Workers 资源

建议登录密码在服务端使用 Argon2id 和成熟库，候选参数为内存 32 MiB、迭代 3、并行度 1，最终参数由部署环境基准测试决定，并满足当期安全基线。客户端保险库 KDF 参数独立，不混用。慢哈希与独立盐的依据见 [OWASP 密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。

普通 Workers 免费档单次请求 CPU 限额为 10ms，且当前 `node:crypto` 不提供原生 Argon2。用户已决定优先验证免费 Workers 加 SQLite Durable Objects，由对象承担同强度 Argon2id 和账号存储；DO 有独立执行限制，不能以普通 Worker 的结果替代其验证。真实 CPU、内存、并发及打包兼容必须实际执行，不能仅在本地 Node 验证。该方案不通过后再考虑 Firebase，暂不考虑 Supabase；保持免费、自定义用户名密码，不为免费额度降低密码哈希强度，也不擅自改成客户端哈希加快速服务端哈希的自创协议。见 [DO 验证记录](feasibility/durable-object.md)、[DO 限制](https://developers.cloudflare.com/durable-objects/platform/limits/) 和 [crypto 兼容范围](https://developers.cloudflare.com/workers/runtime-apis/nodejs/crypto/)。

## 6 加密模型

### 6.1 密钥和数据

手机首次初始化时用系统安全随机数生成 256 位保险库主密钥 VMK。VMK 加密验证账号、密钥、平台名称、自定义名称、账号名、分组、标签、收藏、备注和排序。服务端只能看到密文、匿名标识、版本、设备信息、时间、数量及大小等必要元数据，不能据此声称完全隐藏访问模式。

| 项目 | 建议方案 |
| --- | --- |
| 内容加密 | AES 256 GCM，使用成熟平台库 |
| 每次加密 | 新的随机 96 位 nonce；同一密钥下不得重用，纳入实现检查 |
| 密文绑定 | AAD 包含格式版本、稳定保险库 UUID、条目 UUID、类型、版本及密钥代次 |
| 密码派生 | Argon2id，独立随机盐及明确存储的参数 |
| 主密钥封装 | 用保险库密码派生的密钥加密 VMK |
| 恢复封装 | 独立随机 256 位恢复密钥经标准 HKDF 域分离后封装 VMK |
| 本机便捷解锁 | Android Keystore 保护本机封装，配合系统生物识别或设备凭据 |

客户端 KDF 建议先评估 64 MiB、迭代 3、并行度 1，目标设备解锁等待控制在约 0.3 至 2 秒；这是性能目标，不是已测结果。参数写入封装头，跨端使用同一实现规范；不得自动静默降级。格式支持未来增加算法和参数版本。Argon2id 算法与测试向量见 [RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html)。

保险库密码、VMK、恢复解密密钥和验证密钥不得发送到后端。Google 令牌、登录密码或会话令牌不能用来直接推导 VMK。账号登录密码仅为认证通过 TLS 发送，不能宣称它也从未到达服务端。

### 6.2 密码修改和设备撤销

修改保险库密码时，客户端解锁 VMK，再更新密码封装；普通修改不重加密全部条目。此时旧离线备份仍可由旧密码解密，应保留历史密码或恢复密钥的对应关系。恢复密钥换新也只影响新封装，不能撤回旧备份里的旧密钥。

撤销设备可阻止它继续联网同步，但不能删除离线设备已经获得的 VMK 或 TOTP 密钥。需要阻止旧设备解开未来更新时，手机触发 VMK 轮换并重新加密当前数据，其他受信任设备重新授权；已泄露的 TOTP 密钥仍要到网站重新绑定才能失效。不能声称撤销登录或修改密码即可让旧验证码失效。

端到端加密防止仅取得云端密文的人直接读取内容，不抵御已解锁终端被控制，也不保证新安装设备能识别云端将全部历史一致回滚。历史版本、备份和客户端保存的最高版本用于降低误覆盖及回滚影响，不把它们描述为完整的恶意服务器防护。

## 7 加密同步与冲突处理

### 7.1 同步数据和状态

验证码不参与同步。云端保存验证账号、分组、标签及设置的密文，客户端按本地系统时间计算 TOTP。倒计时刷新、复制、搜索和展开分组不产生云端同步请求。

每个实体具有稳定 UUID、服务端版本和密钥代次。写请求包含 `operation_id`、`base_revision`、密文及必要的关联版本；服务端为已提交事务分配单调递增的同步序号，手机时钟不参与冲突裁决。

手机状态包括：本地已保存待同步、同步中、已同步、存在冲突和失败重试。只有云端事务确认后才能显示“已同步”。Chrome 状态包括：最近成功拉取、检查中、离线缓存、需要重新登录和失败重试。

建议手机在前台打开、修改及网络恢复时同步；前台空闲可每 60 秒检查版本，后台仅尽力执行，不保证实时。Chrome 每次打开弹窗立即检查，使用期间每 60 秒检查，关闭后不保证持续轮询。手动刷新始终可用。失败采用带抖动的指数退避，不因网络错误删除缓存。

### 7.2 原子写入和幂等

云端使用 D1 条件更新实现乐观并发控制：只有 `base_revision` 匹配才接受修改，否则返回 409 和当前版本。同一用户、设备及 `operation_id` 重试返回相同提交结果，避免断网重传产生重复账号或重复删除。

条目更新、历史保存、同步序号和幂等结果必须在同一事务边界提交。版本检查不能写成两个无保护的“先读取、后覆盖”请求。跨表修改使用成熟的 D1 原子操作能力并验证失败回滚；不能用 Worker 内存锁协调不同实例。若开启 D1 读副本，需明确处理写后读和快照的一致性，本版建议从主库读取关键同步结果。

离线手机保留待提交队列，恢复网络后先检查远端变更。同一条目被两部手机同时编辑时，保留本地候选修改和远端版本，由手机选择保留哪份或合并；Chrome 只显示最后成功提交的数据。禁止仅按客户端时间执行最后写入者覆盖。

### 7.3 删除与历史

删除账号先产生带版本的删除记录并进入回收站，默认建议保留 30 天。历史恢复作为一笔新修改提交，不能倒退全局同步序号。旧设备游标早于云端保留窗口时，强制完整重新拉取，再单独处理其本地待提交修改，防止已删除账号被离线旧副本重新带回。

新增导入批次和批量移动应有明确事务或批次状态；失败时报告成功与失败项，不把部分完成显示为全部成功。密钥参数变更、删除恢复和同名条目属于重点冲突测试场景。

## 8 恢复机制

### 8.1 恢复材料

初始化生成一个离线恢复包，统一引导用户保存在手机以外的位置，其中包含两类用途不同的秘密：

| 材料 | 用途 | 服务端处理 |
| --- | --- | --- |
| 平台账号恢复码 | 恢复平台访问、重设登录密码、授权新的管理设备 | 保存独立高熵一次性码的哈希，不保存原码 |
| 保险库恢复密钥 | 在本地解开 VMK 的恢复封装，重设保险库密码 | 不上传原密钥，只保存加密后的恢复封装 |

建议生成若干个至少 128 位随机熵的平台恢复码，每个使用后作废；保险库恢复密钥为 256 位随机值，采用带校验的可抄写编码。两类材料不共用同一值，也不将账号恢复码当成解密密钥。

恢复包还记录平台地址、非秘密账号标识、保险库 UUID、格式版本和保存日期。恢复包本身包含高权限秘密，建议纸质或离线保存；NAS 自动备份不默认保存这份明文恢复包。恢复密钥只有在持有保险库密文及对应恢复封装时才能恢复内容。

### 8.2 场景和行为

| 场景 | 第一版恢复路径 |
| --- | --- |
| 手机丢失，记得两种密码 | 新手机平台登录并下载密文，用保险库密码解锁；取得管理权限需另一部已授权手机批准或账号恢复码 |
| 只需在 Chrome 临时取码 | 平台密码或已绑定 Google 登录，再用保险库密码解锁，无需手机在线 |
| 忘记平台密码 | 使用平台恢复码重设密码、撤销旧会话；仍需保险库密码或恢复密钥解密 |
| 忘记保险库密码 | 已解锁手机可重设封装，或使用保险库恢复密钥解锁后设置新密码 |
| 平台密码和保险库密码都忘记 | 账号恢复码恢复平台访问，保险库恢复密钥恢复解密；缺少其中一项按其能力边界处理 |
| Google 无法登录或被解绑 | 使用平台账号及独立恢复材料，不依赖 Google |
| 所有客户端丢失 | 从 Cloudflare 下载密文；独立账号恢复码和保险库恢复密钥支持完整管理恢复 |
| Cloudflare 账号或服务无法访问 | 从 NAS 取出完整加密备份，在新手机离线导入，凭保险库密码或恢复密钥解密 |
| 误删或错误覆盖 | 手机从回收站或历史版本恢复；超过保留期则使用旧备份 |
| 无任何可解密设备，且保险库密码及恢复密钥都丢失 | 无法解密；重置平台密码或客服不能恢复原始验证密钥 |

离线文件恢复不要求原平台登录、Google 登录、原手机 Keystore 或原域名仍可访问。恢复后可以先离线取码，再创建或接入新的平台账号承载同步。保险库 UUID 与平台账号标识分离，文件保留原保险库 UUID 以验证密文 AAD，不直接改写密文里的身份绑定。

新设备完整恢复前，先核对条目数、分组和至少一个测试账号的真实登录。恢复码消耗、密码重设、新管理设备注册应具备原子边界；并发使用同一码时只能成功一次。账号恢复成功后撤销所有旧会话及旧管理设备授权；NAS 备份凭据建议同时撤销，之后从可信手机重新生成。

## 9 NAS 主动连接备份

### 9.1 网络与任务

NAS 上运行一个小型 Python 程序或 Docker 容器，主动通过 HTTPS 请求 Worker。建议每 10 分钟检查一次云端备份清单，有新版本才下载。通过 NAS 任务计划或容器内调度运行，任务互斥，避免重叠拉取。

不需要公网 IPv4、固定 IP、端口转发、NAS 公网域名或 Worker 加入 Tailscale。家宽运营商 NAT 不影响该出站连接方向，但 NAS 到 Cloudflare 域名的实际连通性、TLS 和访问稳定性仍需现场验证。Tailscale 可继续承担用户远程访问 NAS 的用途。

NAS 使用手机生成的 `backup_reader` 凭据。凭据仅允许读取该保险库的备份清单和快照，不能读取其他用户、修改云端数据、创建会话或提升权限。高熵凭据只在生成时显示，服务端保存哈希，可撤销及轮换；NAS 配置文件限制本机访问权限。该凭据独立于 Google 登录和手机刷新令牌。

### 9.2 完整备份格式

备份是自包含文件，至少包含：

- 魔数、格式版本、导出应用版本、稳定保险库 UUID 和快照版本。
- 全部当前实体密文及恢复所需的分组、标签、收藏和排序密文。
- 每条密文对应的 nonce、认证标签、AAD 元数据和密钥代次。
- VMK 的密码封装、恢复封装、各自盐和 KDF 参数。
- 文件清单、快照时间、条目分页信息和文件摘要。

备份不包含平台登录密码、密码哈希、Google 令牌、服务端签名密钥、设备刷新令牌、账号恢复码原文、VMK 原文或恢复解密密钥原文。

云端从已提交密文生成快照，不需要解密。每份快照固定在一个提交版本，条目和密钥封装必须属于一致的状态；使用固定版本查询及事务边界，不能简单遍历正在变化的当前表。备份生成时若格式或条目数超过配置上限，应报错并保持旧备份，不生成截断的“成功”文件。

NAS 下载时先写临时文件，校验完整长度、格式、目标保险库、快照版本、文件摘要及清单，再原子重命名落盘。云端提供的摘要用于传输和落盘检查，不能证明恶意云端返回的数据可信；密文内容的真实性由客户端导入时的 AEAD 校验判断。NAS 不持有 VMK，因此不能替代解密恢复演练。

### 9.3 保留与故障

每个版本使用独立文件名，禁止以同名覆盖为唯一备份，也不因为云端删除数据自动删除 NAS 历史。保留策略建议为最近 30 天每日备份、最近 12 个月月度备份，并可保留最近 100 次变更快照；具体按容量配置。清理只在新备份验证并落盘后执行，NAS 快照另行保护目录。

网络、鉴权、下载或校验失败时保留最后成功版本，退避重试并记录错误。输出最近成功时间、云端版本、本地版本、失败原因和保留数量；可以接入 NAS 现有通知系统，但本方案不创建通知或定时任务。

云端短期保留可下载快照，建议至少 30 天。NAS 离线超过窗口后至少补取最新完整快照，无法承诺补齐已过期的每个中间版本。NAS 长期离线时，本地恢复点停在最后一次成功下载，不因设置了 10 分钟检查就宣称恢复点永远不超过 10 分钟。

加密备份不能脱离密码和密钥封装版本独立理解。建议每季度在独立测试安装中，从 NAS 文件完成一次离线解密、条目核对和测试账号登录。

### 9.4 恢复目标

默认运行条件正常时，NAS 备份目标为变更提交后约 10 分钟加下载处理时间内完成；这是目标 RPO，不是已验证保证。云端同步覆盖最后成功提交的数据，尚未上传的手机修改不在云端及 NAS 恢复范围。

恢复时间目标是在备份文件和解密材料齐全时，30 分钟内恢复到可取码状态。服务不可用期间手机与 Chrome 的已有本地缓存仍可使用，新设备无法从不可用服务拉取数据，应走离线文件恢复。

## 10 技术架构与选型建议

### 10.1 组件

| 组件 | 建议选型 | 职责 |
| --- | --- | --- |
| Android 手机 | Kotlin、Jetpack Compose、Room、WorkManager、Android Keystore | 完整管理、加解密、离线队列、系统解锁 |
| Chrome 扩展 | TypeScript、React、Manifest V3 | 只读取码、加密缓存、授权登录、自动锁定 |
| 服务端 | TypeScript、Cloudflare Workers、轻量路由及 schema 校验库 | 认证、设备权限、密文同步、版本、备份 API |
| 数据库 | Cloudflare D1 | 用户、身份绑定、设备、会话、密文实体、历史、恢复码哈希、幂等记录 |
| 备份对象 | Cloudflare R2 Standard，私有桶 | 不可变密文快照及清单 |
| NAS 程序 | Python 或 Docker 化命令行程序 | 定时主动下载、校验、原子落盘、保留和状态输出 |
| Google 接入 | 官方身份流程及成熟令牌验证库 | 绑定及快捷登录，不承载保险库恢复 |

客户端密码学算法使用成熟库，手机与 TypeScript 端共享格式规范、测试向量和样本文件。两端不必强行共用同一个运行时或源代码库；必须能互相解密、识别参数及处理格式升级。

第一版采用 Android 原生技术栈。后续增加 iOS 时复用已定义的加密格式、同步协议、权限模型及备份格式，本机安全存储和生物识别通过平台适配实现，不能把 Android Keystore 封装作为新设备恢复的唯一依赖。iOS 的具体客户端技术栈在后续版本确定。

### 10.2 数据表与对象

| 数据 | 主要内容 |
| --- | --- |
| `users` | 内部用户 UUID、用户名、登录密码哈希与参数、账号状态 |
| `external_identities` | 用户、Google issuer 与 sub、展示邮箱、绑定时间 |
| `devices` | 设备 UUID、角色、公钥、状态、会话代次、最后访问时间 |
| `sessions` | 刷新令牌哈希、设备绑定、过期及轮换记录 |
| `vaults` | 稳定保险库 UUID、所有者映射、全局同步序号、加密格式和密钥代次 |
| `vault_envelopes` | VMK 密码封装、恢复封装、盐、参数、版本 |
| `encrypted_entities` | 条目 UUID、类型、版本、nonce、密文、删除状态 |
| `entity_history` | 各提交版本密文和删除记录，用于冲突及历史恢复 |
| `operations` | 幂等 ID、请求摘要、提交结果和有效期 |
| `recovery_codes` | 账号恢复码哈希、使用和撤销状态 |
| `backup_credentials` | 专用备份凭据哈希、权限、撤销及轮换状态 |
| `backup_snapshots` | 固定快照版本、R2 对象键、摘要、大小、生成状态 |

不在云端建立明文平台名称、账号邮箱或标签的搜索索引。所有用户数据查询以服务端认证得到的用户范围过滤，不信任请求参数中的用户归属。保险库内容响应不进入共享缓存，使用适当的禁止缓存响应头。

### 10.3 API 边界

| API 类别 | 允许主体 | 约束 |
| --- | --- | --- |
| 注册登录及刷新 | 未登录或当前会话 | 邀请、限速、令牌轮换；默认不给新管理设备权限 |
| Google 授权及回调 | 登录流程 | 校验 state、nonce、回调归属；绑定操作需手机管理授权 |
| 当前同步版本与增量拉取 | 手机、Chrome | 返回密文、游标和必要封装，严格按用户隔离 |
| 新增更新删除与导入 | 已授权管理设备 | 版本条件、幂等、原子事务；Chrome 一律 403 |
| 回收站与历史恢复 | 已授权管理设备 | 恢复作为新提交，不重置全局序号 |
| 设备授权与撤销 | 已授权手机或恢复授权流程 | 独立重新认证，不能由只读令牌提升权限 |
| 修改密码及绑定管理 | 已授权手机 | 登录密码与保险库封装分别处理 |
| 备份清单及对象下载 | NAS 专用凭据 | 仅固定保险库，只读；默认不允许 Chrome 访问完整备份接口 |
| 账号恢复 | 独立恢复流程 | 一次性高熵恢复码、限速、消耗与撤销原子执行 |

R2 对象不公开访问。Worker 通过绑定读取并鉴权后提供下载；若采用短期下载地址，需限定对象、用途和有效期，并明确地址有效期间的撤销边界。客户端包不包含 R2 管理密钥或 Cloudflare API Token。

## 12 实现约束

- 使用系统安全随机数和成熟密码学库，不自行设计 TOTP、加密算法或认证协议。
- 注册、登录、密码恢复及授权接口执行账号与来源限速；错误信息避免暴露用户是否存在，重试上限不能造成永久无法恢复。
- 日志不记录密码、验证码、验证密钥、二维码原文、恢复材料、Authorization 头或 Google 令牌；审计只记事件类型、匿名主体、结果及时间。
- Chrome 不申请全站读写权限，不注入内容脚本；所有前端输出按纯文本渲染，禁止用账号备注等数据执行 HTML 或脚本。
- 离线文件导入检查大小、版本、KDF 参数上限及完整性，防止损坏文件或超大参数耗尽资源；未知格式不覆盖现有保险库。
- 手机写入密文与本地待同步状态在事务中完成；云端失败不能导致本地新增内容丢失。
- 软件升级和密钥轮换前保留可恢复快照。客户端不支持的新格式只提示升级，不静默重写成旧格式。
- 开发中非必要不增加代码注释；确需注释时使用简洁中文。

## 13 第一版验收标准

以下均须实际执行并保留结果，不能以编译或静态检查通过代替：

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 标准验证码 | RFC 测试向量通过，三种算法及位数周期正确；真站点绑定与登录通过 |
| A02 | Google 验证器迁移 | 单张与多张批次导入、重复扫码、缺张、不支持条目均正确；验证码和条目数核对一致 |
| A03 | 手机管理 | 分组标签收藏排序搜索、批量移动、删除分组和回收站符合规则 |
| A04 | Chrome 只读 | 所有界面无管理入口；使用只读设备令牌直接请求写入、导入、恢复、绑定和提权接口均失败 |
| A05 | 无手机在线 | 手机关机，扩展从已同步数据本地取码；断网与浏览器重启后解锁仍可用 |
| A06 | 锁定 | 闲置、后台、重启、扩展重载后按规则锁定；后台同步不延长解锁 |
| A07 | 多手机同步 | 新增和修改传播到其他端；旧游标触发全量重拉，账号删除不被旧副本复活 |
| A08 | 并发和重试 | 同条目并发返回冲突，断网重复提交不重复创建；事务失败不产生半成品 |
| A09 | 本地与云端泄露检查 | 持久层及云端查不到明文密钥与业务名称，日志无敏感数据；登录密码只有慢哈希 |
| A10 | Google 绑定 | 显式绑定、快捷登录、解绑和错误令牌处理通过；不能按邮箱自动接管账号，Google 不可用不影响独立登录 |
| A11 | 全部设备丢失 | 从干净新手机以独立恢复材料恢复账号、解密并授权管理；完成一个测试网站登录 |
| A12 | 密码遗忘 | 平台恢复不会伪称解密成功，保险库恢复不会自动重设平台身份；并发使用恢复码只成功一次 |
| A13 | NAS 主动备份 | 家宽无入站端口情况下实际拉取成功，重复任务互斥、损坏文件不落为成功备份 |
| A14 | NAS 离线恢复 | 禁用云端连接，在全新安装中仅用 NAS 文件和解密材料恢复分组与验证码并实际登录 |
| A15 | 备份故障和历史 | NAS 断网后保留旧文件并恢复补拉；误删后能从历史文件恢复，清理不误删最后好版本 |
| A16 | 越权和撤销 | 用户隔离、设备撤销、只读权限、NAS 凭据隔离和刷新令牌轮换通过真实 API 测试 |
| A17 | 资源及容量 | 真实 Workers 密码哈希、内存、CPU 和并发测试通过；记录实际方案与账单档位 |
| A18 | 密码及密钥变更 | 密码改封装、新旧备份解密、VMK 轮换及旧设备边界与设计一致 |

建议用专门测试账号和可重置的验证密钥演练，正式迁移前保留原验证器及各网站恢复码，避免测试操作影响唯一登录途径。

## 14 开发顺序与待确定事项

### 14.1 开发顺序

1. 先验证账号密码哈希在真实 Workers 的资源开销、Google 基本身份登录、Android 与扩展跨端加解密和 NAS 家宽拉取；先解决平台可行性。
2. 固定加密格式、恢复材料、只读权限和同步协议，完成标准测试向量、坏文件与越权样例。
3. 实现平台账号、手机本地管理、导入及恢复，再完成加密同步与并发处理。
4. 实现 Chrome 只读客户端、登录解锁、离线取码及自动锁定。
5. 完成 Google 绑定、设备管理、云端快照和 NAS 拉取程序。
6. 执行完整验收，重点演练全设备丢失和云端不可用，再进行真实账号迁移。

### 14.2 待确定与待验证

| 项目 | 当前建议 | 确定方式 |
| --- | --- | --- |
| 最低系统版本 | 实现前按实际手机确定 | 记录测试机 Android 版本和可用生物识别能力 |
| 认证运行成本 | 保留 Workers 付费方案候选 | 真实 Worker KDF 基准，确认能否用免费档及可接受预算 |
