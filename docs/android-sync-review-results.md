## Android 存储与取舍基线

- 完整解密并校验本地候选、固定版本的云端快照及历史来源；已移除 ID 与快照版本必须相同，准备和确认时均检查 head。确认期间云端前进则拒绝，原 pending、比较密文和双方内容不变，最终上传仍受服务端 CAS 保护。
- 按整份业务内容选择；保留本地或恢复历史时，用最新云端 VMK、代次和封装在当前版本上生成新 draft，重新加密改变的实体及显式恢复的 ID，不重新启用旧密码封装。采用云端则确认后结束本地候选，无需重复上传相同快照。
- 确认或取消比较前，将处理前本地、比较时云端和选中的历史保存到本机加密保留副本，按备份摘要去重。最多 16 份、合计 16 MiB，满时拒绝继续，不自动删除；导出和确认删除接口要求已解锁 manager。
- 比较密文与原请求共同保存到 Keystore AtomicFile，重启后预览明文保持锁定。未确认时禁止修改、封装更换和上传；取消仅保留双方并退出比较，不丢弃原 pending。确认后才用新的 operationId 提交，原固定请求不会被静默改写。
- 同一 VMK 的旧历史可由当前已解锁主密钥认证；旧代次需要时要求对应的旧密码/ABR1。比较只描述字段变更及非密钥内容，不展示原始验证密钥。
- PHB110 `SyncReviewStoreTest` 4 项通过，28.986 秒：409 保留原请求、再次变更拒绝、取舍与归档、当前封装、历史递增、显式恢复 ID、取消/重开、reader 拒绝，以及保留空间满时原状态逐字节不变。
- 独立 Node 通过共用提交和转换校验，解密 Android 生成的新快照，核对版本 4、恢复账号、收藏内容及当前封装；测试输出随后删除。
- 构建与 Lint 通过。首次后台测试曾等待超时，最终测试正常打开主 Activity 并只对测试窗口保持亮屏，结束即关闭；未修改系统冻结、安全或休眠策略，超时原因未归因。仅清理正则严格限定的合成 review 命名空间。
