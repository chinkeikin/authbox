# AuthBox 开发路线

每个阶段完成后按实际结果更新状态。没有通过验收的功能不得标记完成。构建检查在相应工程建立后添加，文档初始化阶段只检查内容、链接及 Git 文件范围。

| 阶段 | 交付 | 验证与提交边界 | 状态 |
| --- | --- | --- | --- |
| 0 仓库初始化 | README、需求、开发约定、格式及忽略规则、标准 AGPL-3.0 许可 | 文档一致性、链接、敏感文件忽略、首次提交与远端核对 | 已完成 |

| 2 协议与密码学 | 加密与备份格式、TOTP、恢复材料、schema 和标准向量 | 标准测试、跨端兼容、坏文件和未知版本处理 | 未开始 |
| 3 账号与同步服务 | 账号、设备、只读角色、会话、D1、版本、冲突与历史 | 越权、重放、并发、事务、恢复码单次消费 | 未开始 |

## 提交约定

- 使用小而完整的提交，建议类型为 `docs`、`chore`、`feat`、`fix`、`test`。
- 每个实现步骤通过对应检查后及时推送，不把所有阶段积累成一次提交。
- 提交记录说明变更原因和验证；没有执行的检查明确标出。
- 初始化后先维护主分支；需要评审或风险较高的改动采用短期功能分支及 PR。
- 创建 PR 后附回当前开发聊天，推送后核对远端提交和相关检查结果。
- 标签、正式发布和生产部署按对应阶段单独安排，不与普通推送混为一项操作。
