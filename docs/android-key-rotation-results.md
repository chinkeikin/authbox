# Android 主密钥轮换验证

## 协议与服务端，2026年10月20日

新增 `vault.rotate` 管理操作及 `/v1/vault/rotate`。普通提交不允许改变主密钥代次；轮换必须保持实体 ID 和类型、完整重新加密、更新两种封装，并在同一 SQLite DO 事务中撤销其他会话、将其他有效设备降为只读。保留旧快照及幂等回执，操作摘要隔离普通提交与轮换。

本地实际 workerd + SQLite DO：208 项请求检查通过，含轮换失败事务回滚、同操作幂等重试、接口间重放拒绝、旧主密钥与旧解密材料无法解锁新快照、旧历史可恢复、其他设备会话失效及重新授权。协议单元测试 47 项、HTTP 解析 2 项、生产 bundle 隔离 9 项通过。

随后在真实 Workers Free + SQLite DO 重跑同一套 208 项请求检查，全部通过。测试前后 Workers 付费订阅数量均为 0；临时 Worker、SQLite 命名空间和域名绑定删除已核对。托管证书由 Cloudflare 单独管理，未把绑定删除当作证书删除证明。DO 尾日志观测到轮换成功请求 CPU 3 ms；密码相关 CPU 样本 5 项，133–291 ms，覆盖预设 10 个采样标签中的 5 个，不宣称全标签采样完成。原始本地和云端报告分别在忽略的 `.cache/api/local/latest.json`、`.cache/api/cloud/service-report.json`。

事务边界继续使用 SQLite DO 的同步事务，参考 [Cloudflare storage API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)。部署方案、登录 Argon2id 32 MiB / t=3 / p=1 和保险库 Argon2id 64 MiB / t=3 / p=1 保持不变，未引入依赖。

## Android 流程

- 已同步、已解锁的管理手机验证当前密码或 ABR1，必须设置不同的新保险库密码。随机生成新 32 字节 VMK、新 ABR1、两个新封装及全部实体/清单密文，UUID 和业务内容不变。
- 确认前保留完整旧加密快照，已有保留空间不足时拒绝继续。新恢复密钥只在本次前台显示，须明确确认离线保存；明文密码、VMK 和 ABR1 不写入持久状态。
- 候选以 Keystore 保护的状态持久保存，不替换旧快照；期间禁止编辑、封装更换、普通上传/下载及自动同步。未提交候选可取消，后台隐藏材料并锁定。
- 提交后结果不明时禁止取消，重开后使用旧材料解锁缓存，按原候选和 operationId 重试。确定的 CAS 冲突保留新旧候选后允许取消，取消同时清除本次冲突标记，随后正常同步；不改写原候选覆盖云端。
- 成功核对回执后原子接受新快照、清除待确认状态、删除本机便捷解锁封装并锁定。新密码/ABR1 才能解锁当前快照，旧快照仍需对应旧材料。便捷解锁需重新启用。
- 其他设备会话和刷新凭据失效，重新登录只有只读角色；当前管理手机重新批准后，目标再次进行私钥设备登录才能取得管理权限。已撤销设备不复活。
